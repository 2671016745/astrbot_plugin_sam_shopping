# 山姆代购（astrbot_plugin_sam_shopping）

一个 AstrBot 插件：浏览山姆商品、加购物车、按「极速达 / 全国配」规则计算运费、
生成易支付收款二维码、自动轮询支付状态，并在支付成功后向管理员邮箱发送
「有新的代购消息」通知。管理员可添加商品。

> 适配 AstrBot v4（`astrbot_version: ">=4.0.0"`）。插件目录需命名为
> `astrbot_plugin_sam_shopping`，放到 `AstrBot/data/plugins/` 下。

---

## 一、功能

- 分类浏览：大分类 → 小分类 → 商品（含价格、重量）。
- 购物车：按用户隔离，支持添加、查看、按序号删除、清空（二次确认）。
- 下单：展示商品明细、配送方式、重量、运费、代购费、应付总额，二次确认后生成易支付收款二维码。
- 支付：自动轮询易支付订单状态；支付成功标记订单、通知用户、邮件通知管理员。
- 管理员：通过指令添加商品（持久化）。

## 二、指令

所有指令以**可配置唤醒词**开头，下面用 `sam's` 表示（默认值，可在配置中修改）。

| 指令 | 作用 |
|---|---|
| `sam's help` | 指令帮助、配送方式与运费规则说明 |
| `sam's menu` | 查看全部大分类 |
| `sam's menu <大分类>` | 查看该大分类下全部小分类 |
| `sam's menu <大分类> <小分类>` | 查看该小分类下全部商品 |
| `sam's buy <商品名称> [数量]` | 加入购物车（数量默认 1） |
| `sam's basket` | 查看购物车 |
| `sam's basket delete [序号]` | 列出序号；回复序号或 `basket delete <序号>` 删除 |
| `sam's basket clear` | 清空购物车（需二次确认） |
| `sam's pay [极速达\|全国配]` | 展示费用明细，等待确认 |
| 回复 `确认` / `确认支付` | 生成并发送易支付收款二维码 |
| `sam's add <大分类> <小分类> <商品名称> <价格> [重量kg] [代购费元/件]` | 管理员添加商品 |

也支持中文别名：`帮助 / 菜单 / 购买 / 购物车 / 支付 / 下单 / 添加`，
以及裸回复 `确认`、`确认清空`、`取消`、序号（删除）。

若把唤醒词配置成中文（例如 `wake_word = 山姆`），`山姆 help`、`山姆 menu` 可用；
也兼容 `山姆sam's help` 这种「唤醒词 + sam's + 子指令」的写法。

## 三、运费规则

计算顺序（两种配送方式一致，集中实现在 `core/freight.py::calc_freight`，可单测）：

1. `n100 = floor(计费金额 / 100)`；
2. 基础运费：`计费金额 >= 免邮门槛` 时为 `0`，否则为固定运费；
3. 有效免重 `= 免费重量 + n100 × 每满100元增加的免重`；
4. 续重费 `= max(0, 重量 - 有效免重) × 续重费率`；
5. 满减 `= n100 × 每满100元减免金额`；
6. 运费 `= max(0, 基础运费 + 续重费 - 满减)`，四舍五入保留两位小数。

默认参数（可在配置中修改）：

| 渠道 | 免邮门槛 | 固定运费 | 免费重量 | 续重费率 | 每满100元减免 | 每满100元增加免重 |
|---|---|---|---|---|---|---|
| 极速达 | 99 元 | 10 元 | 15 kg | 1 元/kg | 10 元 | 0 kg |
| 全国配 | 299 元 | 15 元 | 15 kg | 1 元/kg | 10 元 | 5 kg |

### 关于规则歧义的说明

- **「订单金额」的定义**：默认按**商品总金额**（不含运费）计算满减，即
  `freight.amount_base = goods`。若设为 `total`，则按「商品金额 + 按商品金额算出的
  运费」作为满减基数（单步计算，避免循环定义）。推荐保持默认。
- **全国配「每满 100 元减免 5kg 运费」**：按续重费率 1 元/kg，等价于每满 100 元
  增加 5kg 免费重量，因此实现为 `national.per_100_free_weight = 5`；同时保留
  「每满 100 元减免 10 元」的 `per_100_discount = 10`。两者都可在配置中调整。
- 运费最低为 0 元，不会出现负数。

## 四、代购费

代购费是商品金额与运费之外的第三项费用，集中实现在 `core/proxy_fee.py::calc_proxy_fee`。

**全局规则**（配置 `fee` 段）：

| `fee_mode` | 含义 | 对应费率字段 |
|---|---|---|
| `none` | 不收取代购费 | — |
| `per_order` | 按次，整单固定 | `fee_per_order`（元/单） |
| `per_weight` | 按重量 | `fee_per_weight`（元/kg） |
| `per_item` | 按件数 | `fee_per_item`（元/件） |

另有 `fee_min`（每单最低）、`fee_max`（每单封顶，0 为不封顶）、`fee_label`（账单上的费目名称，默认「代购费」）。

**单个商品单独设置**：添加商品时第 7 个参数就是「单件代购费（元/件）」，例如

```
sam's add 水果 车厘子 智利车厘子 89.9 1.5 5
```

表示该商品按 `5 元/件 × 数量` 计取代购费，**优先于全局规则**；没填的商品仍按全局规则计算。
想只设代购费、重量用默认值，用 `-` 占位：

```
sam's add 水果 车厘子 智利车厘子 89.9 - 5
```

**结账时的说明**：`sam's pay` 的预览会逐条列出计算过程与金额，例如

```
跑腿费（按件数）：
· 车厘子：5 元/件 × 2 件（商品单独设置） = 10 元
· 蓝莓：2.00 元/件 × 3 件 = 6.00 元
跑腿费合计：16.00 元
应付总额：xxx 元
```

同一份明细会写进订单（`proxy_fee` + `proxy_fee_detail`，重启后仍可回显），
也会出现在支付成功通知与管理员邮件里。菜单里设了单件代购费的商品会标注
「单件代购费 X 元/件」。

## 五、配置

插件目录下 `_conf_schema.json` 定义了配置，AstrBot 会在
`data/config/astrbot_plugin_sam_shopping_config.json` 生成配置文件，可在 WebUI
「插件 → 配置」中修改，也可直接编辑该 JSON。

主要配置项：

- **常规**：唤醒词 `wake_word`、别名 `wake_aliases`、管理员 ID `admins`、
  默认配送方式 `default_channel`、两种配送方式的启用开关、店铺名。
- **运费**：满减基数、默认重量、极速达/全国配的全部规则参数。
- **代购费**：计费方式 `fee_mode`（不收/按次/按重量/按件数）、对应费率、
  每单最低/封顶、账单费目名称 `fee_label`。单个商品的代购费在 `add` 指令里设置。
- **易支付**：网关地址 `gateway`、`pid`、`key`（加密字段）、支付方式 `pay_type`、
  签名方式、创建/查询接口路径、`notify_url`/`return_url`、判定已支付的状态值、超时。
- **SMTP**：服务器、端口、账号、密码（加密字段）、发件人、管理员通知邮箱。
- **轮询**：间隔、订单支付超时、连续查询失败告警阈值。
- **订单**：订单号前缀、二次确认有效期、邮件最大重试次数。
- **存储**：商品/订单/购物车文件路径（留空则用 `data/plugin_data/astrbot_plugin_sam_shopping/`）。

### 易支付对接

默认按常见易支付（`mapi.php` 创建 + `api.php?act=order` 查询）实现：

- 创建：`GET {gateway}/mapi.php?pid=&type=&out_trade_no=&money=&name=&notify_url=&return_url=&param=&sign=&sign_type=MD5`
- 查询：`GET {gateway}/api.php?act=order&pid=&key=&out_trade_no=`（或 `sign` 签名方式）

签名 = `md5(按参数名升序拼接的 k=v&... + 商户密钥)`；如网关对参数做了 URL 编码，
把 `sign_urlencode` 设为 `true`。

已支付判定：`status` 在 `paid_status_values`（默认 `[2]`）中，或
`trade_status` 在 `paid_trade_status`（默认 `TRADE_SUCCESS/PAID/SUCCESS`）中。
不同网关取值不同，请按实际情况调整。

## 六、支付与通知流程

1. 用户 `pay` → 插件展示明细并等待确认；
2. 用户确认 → 创建唯一订单号（前缀 + 时间戳 + 4 位随机），调用易支付生成收款二维码并发送图片；
3. 后台每 `interval` 秒轮询所有待支付订单；
4. 支付成功 → 订单置为已支付（幂等，重复轮询不会重复处理）→ 通知用户 → 向管理员发送邮件；
5. 超时未支付 → 订单关闭并通知用户；查询/生成/邮件失败都会记录日志。

邮件主题包含「有新的代购消息」，正文包含：订单号、用户 ID/昵称、商品明细与数量、
商品金额、配送方式、重量、运费、代购费（含计算明细）、应付总额、支付时间。

## 七、安全与健壮性

- `add` 指令校验管理员身份（配置的用户 ID 列表，可选回退 AstrBot 平台管理员）。
- 易支付密钥、SMTP 密码在配置中标记为 `secret`，不写入日志或聊天。
- 支付通知幂等：订单上持久化 `email_sent` / `email_attempts`，重启后不会重复发邮件。
- 用户输入校验：分类/名称长度、价格与重量范围、数量必须为正整数。
- 关键操作记录日志，便于排查支付与邮件问题。

## 八、数据存储

- 商品：`products.json`，购物车：`carts.json`，订单：`orders.json`。
- 默认位于 `AstrBot/data/plugin_data/astrbot_plugin_sam_shopping/`，重启不丢失。
- 写入使用临时文件 + 原子替换，避免写入中断导致损坏。
